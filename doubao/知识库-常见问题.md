# 知识库：抖音点赞归档常见问题

## 这个方案是干什么的

把抖音账号里点赞过的视频整理成本地归档：清单（含每条视频的可点击链接）、无水印视频文件、按视频发布年份分好的目录，以及一份数据分析报告。

## 为什么不直接调接口

抖音的接口有动态签名（`a_bogus`）。实测三条路都不通：

- 裸请求：`403 Blocked by ArgusSecurityPlugin Uifid Not Found`
- 调用页面里的 `byted_acrawler.frontierSign`：只返回旧的 `X-Bogus`，接口要 `a_bogus`，报 `Sign Invalid`
- 复用浏览器已签好名的 URL 重放：返回网页外壳，因为签名绑定了完整 URL 且有时效

所以改成"不生成请求，只读响应"：用真实的 Chrome 打开点赞页，让页面自己发请求，拦截返回的 JSON。

## 为什么必须开有界面的浏览器

无头（headless）模式下，抖音页面只渲染出导航和页脚，接口一次都不调用。必须 `headless: false`。在 Linux 无桌面的服务器上，可以用 WSLg 的 Wayland（`--ozone-platform=wayland`）。

## 为什么滚动不加载更多

真正的滚动容器是 `.route-scroll-container`，不是 `window`。只滚 `window` 会卡在 60 条不动。

## 为什么跑到一半内存爆掉

点赞页是无限滚动，滚过的卡片**永不释放**。实测每页（18 条）多约 470 个 DOM 节点、4.4 MB JS 堆，平均每条视频占 240KB —— 因为应用还保存着每条视频的完整 JSON。

反直觉的地方：禁掉图片想省内存，结果**更费**（失败图片会重试并生成占位元素）。有效办法只有加内存。

## 为什么只有 1.3 万条，我账号有 2.4 万

网页端对「喜欢」列表有截断：约 1000 页之后接口不再返回数据，但 `has_more` 仍然是 1。多次独立运行都停在同一位置，判定为服务端限制。

想拿全只能走官方渠道：抖音 → 设置 → 隐私设置 → 个人信息管理 → 下载个人信息。这是法律赋予的权利，合规、无风控风险，缺点是要等几天。

## 能拿到点赞时间吗

不能。接口只返回视频的 `create_time`（发布时间）。所以所有"按年份"的统计实际是**按视频发布年份**。

## 采集频率怎么设置才安全

第二个参数是每页延迟（毫秒）：

- `2500`（默认）≈ 每页 4 秒，最稳
- `1000` 是下限，再低容易触发滑块验证码
- 触发验证码后只能人工拖动滑块，无法自动化

## 出现验证码怎么办

两种办法：

1. 如果浏览器窗口能看见，直接在窗口里拖滑块
2. 看不见窗口（例如 WSLg 渲染异常）时，用 `remote_collect.mjs`：它把浏览器画面推流到网页，你在网页里拖动鼠标，事件反向注入浏览器

后者是自己实现的"远程桌面"，因为 TigerVNC / noVNC 在无 root 环境里起不来（缺 `/usr/bin/xkbcomp`）。

## 下载的视频有 watermark 吗

没有。从详情接口的 `video.play_addr` 取的是无水印原片。优先级：

1. `video.play_addr`（无水印）
2. `video.play_addr_h264`
3. `video.bit_rate[]` 按码率降序
4. `video.download_addr`（带水印，兜底）

下载只需 `user-agent` 和 `referer`，不需要 cookie。但直链有时效，必须拿到就下。

## 怎么验证下载完整

不用 ffmpeg（Playwright 自带的那个是录屏精简版，不认 mp4）。用 Chromium 打开 `file://` 路径播放，`video.readyState === 4` 说明完全可解码。

## 定时任务怎么写

Windows 计划任务 → `wsl.exe` → 一个 bash 脚本。注意两个坑：

- 计划任务用的是**非登录 shell**，PATH 里没有 `~/.local/bin`，直接 `node` 会 `exit 127`，必须写绝对路径
- `wsl.exe -e` 返回后后台进程会被杀掉，要用 `systemd-run --user` 托管

## 数据安全

`profile/`（登录态）、`likes-all.jsonl`（浏览记录）、`videos/` 都含个人数据。发布代码时务必用 `.gitignore` 排除，只公开代码和方法。
